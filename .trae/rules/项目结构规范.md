# 项目结构规范 - 课表大屏展示系统
生效方式：始终生效

## 1. 项目技术架构
- 前端：原生 HTML + CSS + JavaScript，纯静态，发布到 GitHub Pages（`gh-pages` 分支）
- 数据来源：GitHub Actions 定时运行 Python 脚本登录正方教务系统拉取课表，生成静态 JSON 随前端一起发布，
  线上不需要任何后端服务器（同时避开 `*.vercel.app` 在国内被屏蔽的问题）
- 本地调试：`api/` 下的 Python 版本可在本机起 HTTP 服务，仅供开发时查看接口返回
- 手动调课：前端 localStorage 覆盖层，优先级高于正方课表数据
- 学号密码：只存在于 GitHub Actions Secrets 与本地 `.env`，前端代码严禁出现

## 2. 整体目录结构

```
timetable-system/
├── public/                     # 前端静态资源（发布到 GitHub Pages）
│   ├── index.html              # 首页大屏展示页面
│   ├── css/
│   │   └── style.css           # 全局样式（日间 / 黑夜主题 CSS 变量）
│   ├── js/
│   │   ├── main.js             # 大屏核心逻辑：数据请求、课程筛选、倒计时、进度条、主题切换
│   │   └── override.js         # 手动调课覆盖层：localStorage 增删改查、数据合并
│   └── data/
│       └── timetable.json      # 课表数据（Actions 定时生成，不入库）
├── scripts/
│   └── fetch_timetable.py      # 登录正方 → 拉课表 → 标准化 → 写出上面的 JSON
├── .github/workflows/
│   └── update-timetable.yml    # 定时抓取 + 把 public/ 发布到 gh-pages 分支
├── api/                        # 仅本地调试用的 Python 版本（线上不部署）
│   ├── timetable.py            # 本地 HTTP 入口：python api/timetable.py
│   ├── config.py               # 配置常量：学年学期、教学周起始、作息时间表
│   └── zfn_api.py              # 正方接口库源码（已内联，无需 pip 安装）
├── requirements.txt            # Python 依赖（requests / rsa / pyquery）
├── .env.example                # 环境变量模板（复制为 .env 使用）
├── requirements.md             # 业务需求文档（功能、UI、验收标准）
└── README.md                   # 项目说明：本地开发、Actions 密钥、GitHub Pages 部署步骤
```

## 3. 文件命名规则
1. 文件名全部小写，多个单词用短横线`-`分隔，禁止空格、中文文件名
2. HTML文件：语义命名，`index.html`
3. JS/CSS/Python：语义化命名，禁止使用 `test.js`、`temp.css` 等临时名称
4. 目录名全小写，语义清晰

## 4. 前端代码规范
### 4.1 基础要求
1. 使用原生 HTML、CSS、JavaScript，**禁止引入 Vue/React/jQuery 等任何前端框架**
2. CSS 使用 CSS 变量统一管理日间/夜间主题颜色，主题切换通过修改根元素变量实现，添加 transition 平滑过渡
3. 移动端优先设计，使用 viewport 标签适配，优先适配安卓竖屏手机
4. 页面布局保证一屏展示，不出现滚动条
5. 所有核心逻辑必须写清晰注释：课程筛选、倒计时计算、进度条计算、长间隔判断、数据合并

### 4.2 字号层级（严格遵守）
优先级从高到低：
- 倒计时数字：56~72px，超粗
- 课程名称：48~64px，超粗
- 教室名称：40~52px，加粗
- 上课时间：24~28px
- 老师名字：18~20px
- 顶部日期+星期：16~18px
- 顶部实时时钟：20~24px，加粗

### 4.3 功能模块要求
1. **主题切换**：右上角🌞/🌙按钮，一键切换日间/夜间，切换带平滑过渡动画，用户选择记录在 localStorage
2. **倒计时**：每1秒刷新一次，数字变化带平滑过渡动画
3. **进度条**：待上课和上课中状态（间隔≤48小时）均渲染，每秒更新，平滑过渡
4. **长间隔判断**：距离下一节课超过48小时时，隐藏倒计时和进度条，显示假期提示文案
5. **数据合并**：正方课表数据 + localStorage手动覆盖层，手动覆盖层优先级更高

## 5. Python 代码规范（正方数据抓取与本地调试）
### 5.1 技术栈
1. Python 3.x
2. 使用 zfn_api 库（GitHub: openschoolcn/zfn_api），源码已内联在 `api/zfn_api.py`（上游无 setup.py、未发布 PyPI）
3. 轻量实现，无重型框架：本地调试用标准库 `http.server`，抓取脚本直接复用同一模块

### 5.2 安全要求（严格遵守）
1. 学号、密码、正方系统 base_url 只从环境变量读取（本地读 `.env`，线上由 Actions Secrets / Variables 注入），**严禁硬编码在任何代码文件中**
2. 前端代码、GitHub 公开仓库中绝对不能出现学号密码
3. 接口不暴露正方系统原始数据，只返回标准化格式

### 5.3 数据格式
本地接口 `GET /api/timetable` 与线上静态文件 `public/data/timetable.json` 的字段完全一致：
- 输入：无（配置在环境变量中）
- 输出：标准化课程列表 JSON
- 格式：
```json
{
  "courses": [
    {
      "name": "高等数学",
      "weekday": 1,
      "startTime": "08:30",
      "endTime": "10:00",
      "classroom": "实训楼203",
      "teacher": "张老师"
    }
  ],
  "updatedAt": "2026-09-24 12:00:00",
  "source": "zf_api"
}
```

### 5.4 缓存与更新
1. 本地调试接口带内存缓存（TTL 建议 30~60 分钟），避免每次访问都重新登录正方
2. 缓存失效后重新登录拉取
3. 线上数据由 Actions 每小时重新生成一次，不依赖进程内缓存；返回中带 `updatedAt` 字段，前端可据此判断数据新旧
4. 抓取失败时 Workflow 直接报错，`gh-pages` 保留上一次成功的数据，**不得把课表刷成空白**

## 6. 开发顺序要求（严格按此顺序）

1. **第一步**：开发 `public/index.html` + `css/style.css` + `js/main.js`
   - 用本地模拟数据（写死 2~3 条测试课程）
   - 完成：页面布局、字号、日夜主题切换、倒计时逻辑、进度条渲染、长间隔判断
   - 完成后暂停，等待前端预览确认
2. **第二步**：开发 `js/override.js`
   - 手动调课覆盖层：新增 / 修改 / 跳过课程，存 localStorage
   - 数据合并逻辑：正方数据 + 本地覆盖层合并
   - 完成后暂停
3. **第三步**：开发数据层 `api/timetable.py` + `api/config.py` + `scripts/fetch_timetable.py`
   - 封装 zfn_api 登录、拉课表、数据格式转换、缓存
   - 抓取脚本复用同一模块，登录正方后在本地生成 `public/data/timetable.json`
   - 完成后暂停，等待接口测试
4. **第四步**：联调
   - 本地：前端读 `http://127.0.0.1:8000/api/timetable`
   - 线上：前端读同源静态文件 `data/timetable.json`
   - 验证数据合并逻辑正常
5. **第五步**：配置自动更新
   - 编写 `.github/workflows/update-timetable.yml`，在仓库 Settings 里配置 Secrets / Variables
   - 确认 Pages 的发布分支为 `gh-pages`，目录 `/(root)`
6. **第六步**：编写 README.md
   - 本地开发步骤
   - GitHub Actions 密钥配置与自动更新说明
   - GitHub Pages 部署步骤

## 7. 硬约束

- 禁止引入任何前端框架（Vue/React/jQuery/Bootstrap 等），保持纯原生
- UI 严格遵循 AI 科技简约方案 1：卡片圆角 20px，极淡径向渐变背景，轻微卡片阴影，细边框
- 学号密码严禁出现在前端代码或 GitHub 公开仓库
- 所有核心业务逻辑必须添加注释
- 页面必须保证安卓手机竖屏一屏展示完，无滚动
- 倒计时、课程名称、教室名称三者字号必须最大，满足快速找教室需求
