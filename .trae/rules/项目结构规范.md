# 项目结构规范 - 课表大屏展示系统
生效方式：始终生效

## 1. 项目技术架构
- 前端：原生 HTML + CSS + JavaScript，纯静态，部署到 GitHub Pages
- 后端：Vercel Serverless Functions（Python），调用 zfn_api 拉取正方教务系统课表
- 手动调课：前端 localStorage 覆盖层，优先级高于正方接口数据
- 学号密码：存储在 Vercel 环境变量中，前端代码严禁出现

## 2. 整体目录结构
```

timetable-system/
├── public/                     # 前端静态资源（部署 GitHub Pages）
│   ├── index.html              # 首页大屏展示页面
│   ├── css/
│   │   └── style.css           # 全局样式（日间 / 黑夜主题 CSS 变量）
│   └── js/
│       ├── main.js             # 大屏核心逻辑：时间计算、课程筛选、倒计时、主题切换、进度条渲染
│       └── override.js         # 手动调课覆盖层：localStorage 增删改查、数据合并
├── api/                        # Vercel Serverless Functions（Python）
│   ├── timetable.py            # GET /api/timetable：登录正方 → 拉课表 → 格式化 → 缓存 → 返回
│   └── config.py               # 配置常量：学年学期、缓存 TTL、正方系统参数
├── requirements.txt            # Python 依赖列表（zfn_api 等）
├── vercel.json                 # Vercel 部署配置（路由、Python 运行时）
├── requirements.md             # 业务需求文档（功能、UI、验收标准）
└── README.md                   # 项目说明：本地开发、Vercel 部署、GitHub Pages 部署步骤

```

## 3. 文件命名规则
1. 文件名全部小写，多个单词用短横线`-`分隔，禁止空格、中文文件名
2. HTML文件：语义命名，`index.html`
3. JS/CSS/Python：语义化命名，禁止使用 `test.js`、`temp.css` 等临时名称
4. 目录名全小写，语义清晰

## 4. 前端代码规范
### 4.1 基础要求
1. 使用原生 HTML、CSS、JavaScript，**禁止引入 Vue/React/jQuery 等任何前端框架**
2. CSS 使用 CSS 变量统一管理日间/夜间主题颜色，主题切换通过修改根元素变量实现，添加 transition 平滑过渡
3. 移动端优先设计，使用 viewport 标签适配，优先适配安卓竖屏手机
4. 页面布局保证一屏展示，不出现滚动条
5. 所有核心逻辑必须写清晰注释：课程筛选、倒计时计算、进度条计算、长间隔判断、数据合并

### 4.2 字号层级（严格遵守）
优先级从高到低：
- 倒计时数字：56~72px，超粗
- 课程名称：48~64px，超粗
- 教室名称：40~52px，加粗
- 上课时间：24~28px
- 老师名字：18~20px
- 顶部日期+星期：16~18px
- 顶部实时时钟：20~24px，加粗

### 4.3 功能模块要求
1. **主题切换**：右上角🌞/🌙按钮，一键切换日间/夜间，切换带平滑过渡动画，用户选择记录在 localStorage
2. **倒计时**：每1秒刷新一次，数字变化带平滑过渡动画
3. **进度条**：待上课和上课中状态（间隔≤48小时）均渲染，每秒更新，平滑过渡
4. **长间隔判断**：距离下一节课超过48小时时，隐藏倒计时和进度条，显示假期提示文案
5. **数据合并**：正方接口数据 + localStorage手动覆盖层，手动覆盖层优先级更高

## 5. 后端代码规范（Vercel Functions）
### 5.1 技术栈
1. Python 3.x
2. 使用 zfn_api 库（GitHub: openschoolcn/zfn_api）
3. 轻量 HTTP 处理，无重型框架

### 5.2 安全要求（严格遵守）
1. 学号、密码、正方系统 base_url 全部从 Vercel 环境变量读取，**严禁硬编码在任何代码文件中**
2. 前端代码、GitHub 公开仓库中绝对不能出现学号密码
3. API 接口不暴露正方系统原始数据，只返回标准化格式

### 5.3 接口设计
**GET /api/timetable**
- 输入：无（配置在后端环境变量中）
- 输出：标准化课程列表 JSON
- 格式：
```json
{
  "courses": [
    {
      "name": "高等数学",
      "weekday": 1,
      "startTime": "08:30",
      "endTime": "10:00",
      "classroom": "实训楼203",
      "teacher": "张老师"
    }
  ],
  "updatedAt": "2026-09-24 12:00:00",
  "source": "zf_api"
}
```

### 5.4 缓存策略

1. 课表数据带内存缓存（TTL 建议 30~60 分钟），避免每次请求都登录正方
2. 缓存失效后重新登录拉取
3. 接口返回中包含 updatedAt 字段，前端可判断是否需要刷新

## 6. 开发顺序要求（严格按此顺序）

1. **第一步**：开发 `public/index.html` + `css/style.css` + `js/main.js`
   - 用本地模拟数据（写死 2~3 条测试课程）
   - 完成：页面布局、字号、日夜主题切换、倒计时逻辑、进度条渲染、长间隔判断
   - 完成后暂停，等待前端预览确认
2. **第二步**：开发 `js/override.js`
   - 手动调课覆盖层：新增 / 修改 / 跳过课程，存 localStorage
   - 数据合并逻辑：正方数据 + 本地覆盖层合并
   - 完成后暂停
3. **第三步**：开发后端 `api/timetable.py` + `api/config.py`
   - 封装 zfn_api 登录、拉课表、数据格式转换、缓存
   - 完成后暂停，等待接口测试
4. **第四步**：前后端联调
   - 前端对接 /api/timetable 接口
   - 验证数据合并逻辑正常
5. **第五步**：编写 README.md
   - 本地开发步骤
   - Vercel 部署步骤（环境变量配置、vercel.json）
   - GitHub Pages 部署步骤

## 7. 硬约束

- 禁止引入任何前端框架（Vue/React/jQuery/Bootstrap 等），保持纯原生
- UI 严格遵循 AI 科技简约方案 1：卡片圆角 20px，极淡径向渐变背景，轻微卡片阴影，细边框
- 学号密码严禁出现在前端代码或 GitHub 公开仓库
- 所有核心业务逻辑必须添加注释
- 页面必须保证安卓手机竖屏一屏展示完，无滚动
- 倒计时、课程名称、教室名称三者字号必须最大，满足快速找教室需求
